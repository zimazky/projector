# PR 18 — CI для PR/push и адресная политика аудита

Дата: 1 ноября 2026 года. Третий блок этапа 8 [объединённого плана](remediation_plan_2026-10-31_ru.md). База — `0a00db9` («Этап 8. Убран forceUpdate»); рабочее дерево до начала работы чистое. Изменения выполнены и проверены локально; коммит, удалённый PR и публикация агентом не выполнялись.

## Результат

Раньше workflow работал только при push в master. Он запускал проверки приложения и упаковщик Pages, но не запускал npm audit и не проверял PR. Теперь workflow реагирует на pull_request, push в любую ветку и ручной запуск.

Задача build сохраняет npm ci, проверки типов приложения/e2e, ESLint, Jest, Chromium и production-сборку с проверкой состава Pages. Добавлен `test:ci` для тестов инструментов проверки. Для PR, других веток и ручного запуска сборка получает значения ci-placeholder. Секреты приложения используются только в шаге сборки Pages при push в master; загрузка Pages-артефакта ограничена тем же условием.

Отдельная задача audit устанавливает дерево с ignore-scripts и выполняет `npm run audit:ci`. Deploy зависит от успешных build **и** audit и дополнительно ограничен push в master. Права pages:write/id-token:write перенесены из общего workflow в deploy. Проверки устаревших запусков одной ветки/PR могут отменяться; публикации имеют отдельную последовательную группу concurrency.

Настройки защиты ветки не менялись: обязательность build/audit при слиянии задаётся в настройках репозитория. Сам workflow блокирует свой deploy при неуспешных проверках. Выполнение в GitHub Actions после push ещё не проверялось.

## Сбор и проверка аудита

Новые скрипты `scripts/audit-dependencies.mjs` и `scripts/audit-policy.mjs`:

- выполняют оба режима npm audit, включая production после отказа полного аудита;
- сохраняют исходные stdout/stderr до проверки политики, затем структурированную сводку;
- различают корректный отчёт с advisory, отсутствие находок и ошибку получения/обработки;
- проверяют схему npm audit v2, метаданные, граф via, пути и установленные версии lockfile;
- разрешают циклы метауязвимостей при наличии исходной advisory и отклоняют неразрешимый граф;
- ограничивают время каждого npm-процесса 60 секундами, сетевого запроса — 15 секундами с одной повторной попыткой;
- возвращают код 0 при допуске политики, 1 при блокирующих находках, 2 при ошибке аудита/политики.

Коды CLI дополнительно проверены через настоящий дочерний процесс Node с подменённым npm, включая другой регистр каталога запуска в Windows. Для определения запускаемого модуля используется [import.meta.main](https://nodejs.org/download/release/v24.4.0/docs/api/esm.html#importmetamain), доступный в используемом Node 24.12. Импорт скрипта в тесты не запускает npm и не создаёт отчёты.

В `security/audit-policy.json` находится пустой массив исключений. Любой high/critical останавливает проверку, если нет отдельного действующего исключения для точной комбинации scope/package/advisory/path/version/severity с owner, reason и expiresOn. GHSA либо стабильный npm source идентифицирует конкретную advisory. Числовой baseline не используется: замена одной advisory другой при прежнем количестве находок блокируется. Изменение пути, установленной версии, области аудита или severity также требует отдельного решения. В дату expiresOn по UTC запись уже недействительна.

Результат passed с auditStatus=advisories означает допуск политикой, а не отсутствие уязвимостей. Moderate/low остаются в отчёте. Исторический список остаточных advisory этапа 2 не используется для подавления CI.

## Отчёты и публикация

В CI stdout полного/production-аудита, stderr и summary загружаются отдельным артефактом dependency-audit на 14 дней, в том числе после ошибки команды. Браузерные отчёты сохраняются отдельно на 7 дней. При отмене workflow загрузка не гарантируется. Ошибка установки до запуска аудита видна в журнале задачи и не создаёт успешного статуса аудита.

Существующий упаковщик Pages сохранён: в публикацию идут только index и разрешённые ресурсы приложения. Новые тесты проверяют отсутствие копирования отчёта аудита и отказ при появлении лишних JSON/каталогов внутри Pages.

Добавлены [.env.example](../.env.example) с пустыми значениями, [инструкция CI](ci_security_ru.md) и описание команд в README. Правила событий и прав сверены с официальной документацией [GitHub Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#pull_request), поведение exit code — с [npm audit](https://docs.npmjs.com/cli/v11/commands/npm-audit/#exit-code).

## Границы и продолжение

Проверки выполнены на Windows с Node 24.12.0/npm 11.12.1. Workflow валидирован actionlint, но ещё не исполнялся на GitHub runner. Новая чистая установка в отдельном checkout на этом шаге не выполнялась; зависимости и lockfile не менялись. Google/погода в Chromium подменены на сетевой границе; реальные операции Drive не выполнялись. Код приложения и форматы документов/сессий/IndexedDB не менялись.

Этап 8 продолжается: границы модулей и импортов, постепенное усиление правил Promise/hooks/noUncheckedIndexedAccess, финальная приёмка нового checkout и сверка документации. Общий календарь остаётся отдельной следующей функцией.
