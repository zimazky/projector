## Восстановление и формат

`MainStore.init` сначала восстанавливает локальные документы и только затем запускает Google API. Ошибка готовности Google обрабатывается отдельно; зависшая загрузка не задерживает вкладки. Это восстановление при доступных ресурсах приложения, а не реализация service worker или полного offline-start.

`DocumentFormat` — общая проверка содержимого для Drive, применения импорта, локального восстановления и экспорта. Внешний JSON получает `schemaVersion: 1`; доменные данные и dirty-сравнение не включают номер формата. Проверяются все три массива, проекты, уникальность имён, ссылки событий на проекты, типы EventDto, настоящие календарные даты, время, длительность, конечные суммы и расписание. Конец должен следовать за началом, выполненное событие не может иметь расписание, повторяемое событие не должно выходить за день. Неподдерживаемые версии отклоняются, включая версию вложенного содержимого сессии.

Неверсионированный JSON мигрирует на копии. Даты с дефисами приводятся к точкам; отсутствующие проекты, на которые ссылаются старые события, восстанавливаются с прежним стандартным оформлением black/gray. В v1 отсутствующая ссылка считается ошибкой. Исходные файлы Drive не заменяются: сохраняется политика отдельных версий этапа 4. Старые обезличенные фикстуры проверены повторным round-trip без изменения оригинала. Удалены прежние небезопасные альтернативные парсеры из файла типов.

`DocumentSessionFormat` проверяет полный граф localStorage: уникальные ID, соответствие порядка составу документов, активную вкладку, ref/state/sync, числовые версии и временные метки. Содержимое каждой вкладки проходит тот же `DocumentFormat`. Все доменные сторы подготавливаются до замены сессии в памяти. Неполный или неверный снимок не создаёт частично восстановленные вкладки. Повторное восстановление не дублирует уже открытые документы. При перезапуске сбрасываются операции и проверка Drive, сохраняются локальные изменения и неизвестная база старых снимков.

## Атомарная локальная запись и резервирование

Введён интерфейс `DocumentPersistence` и реализация `LocalDocumentPersistence`. Новый `documentTabs` содержит `schemaVersion: 1`, метаданные и содержимое всех вкладок. Один `setItem` заменяет весь снимок: сбой записи оставляет предыдущую сессию целиком. Раздельные записи `document_<id>` больше не выполняются.

При чтении старого формата исходные строки метаданных и документов сохраняются в памяти. Перед первой записью нового формата они архивируются в `documentTabs.backup.N`; существующий архив никогда не перезаписывается другим исходником. Повтор для того же исходника использует существующую копию. Старые `document_*` остаются доступными. Ошибка создания архива запрещает замену старой сессии, но не мешает работать с уже восстановленными данными в памяти. Само восстановление не меняет исходные записи.

Ошибки чтения, запрет Storage и исчерпание квоты показываются в приложении. Редактирование остаётся доступным, последние правки можно скачать как `projector-session.json`, исходные записи и архивы — как `projector-recovery-source.json`. После восстановления доступа или освобождения квоты повтор локальной записи сохраняет текущее содержимое. После ошибки проверки исходника автоматическая запись блокируется, чтобы новый документ не затёр повреждённую сессию; при пустой сессии можно повторить восстановление. При работе в памяти нужно экспортировать данные до перезагрузки.

Меню «Экспортировать документ» скачивает отдельный JSON v1 без Google. Архив всей сессии не является отдельным документом для открытия через Drive. Автоматического импорта архивов или интерфейса выбора старой резервной копии этот этап не вводит: они сохраняют данные для ручного восстановления. Для возврата к прежнему коду нужно экспортировать отдельные документы и исходные записи, а не считать откат кода миграцией данных.

localStorage выбран для ограниченного текущего этапа: объединение содержимого и метаданных устраняет разрыв между записями без нового асинхронного протокола. Запись синхронная и сериализует всю сессию; точные fingerprints и резервные исходники дополнительно занимают место. Для синтетических 1000 / 10 000 / 50 000 событий размер строки data + два точных fingerprint составляет приблизительно 0,69 / 6,97 / 35,13 МБ в UTF-16, без архивов и прочих метаданных; это расчёт размера строки, а не измерение квоты браузера. Синтетическая оценка размеров сохранена в `artifacts/remediation-stage5/storage-sizing.json`. Для больших историй предпочтительна отдельная реализация `DocumentPersistence` на IndexedDB с транзакцией содержимого и метаданных; она не внедрялась без данных о реальных объёмах и отдельной проверки асинхронного жизненного цикла. Квота не обходится, вместимость произвольной сессии не обещается.

## Google API и вход

Общий login Promise завершается при отказе согласия, закрытии или блокировке popup, синхронном исключении и таймауте 120 секунд. Каждая попытка получает собственные callback-замыкания; поздний callback предыдущей попытки не подтверждает и не отменяет следующую. Успешный ответ передаёт токен GAPI без логирования. После неудачной инициализации сервис запускает init повторно при следующем входе.

Загрузка скриптов и client init ограничены 15 секундами. Ошибка одного скрипта отменяет ожидание второго; таймеры и обработчики освобождаются. Поздний callback client init после таймаута не объявляет успешную готовность. Использованы описанные Google [callback и error_callback](https://developers.google.com/identity/oauth2/web/reference/js-reference); реальный OAuth проверяется отдельно от автоматических заглушек.

`prom` уже переведён на async/await в этапе 4; теперь нормализация дополнительно сохраняет HTTP-код, чтобы ожидаемый 404 удаления не терялся после обёртки ошибки. `driveQueryLiteral` централизует экранирование апострофов и обратной косой черты в имени и ID папки для `q`. Это отдельный шаг перед URL-кодированием, как в [контракте поиска Drive](https://developers.google.com/workspace/drive/api/guides/search-files).
