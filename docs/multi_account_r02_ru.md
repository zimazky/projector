# R02: идентичность событий и происхождение повторений

Дата: 1 ноября 2026 года. Этап [плана реализации](multi_account_implementation_plan_ru.md).

## Внутренний режим и совместимость

Новый путь включается параметром `new EventsStore(projectsStore, true)`. В точке сборки приложения и в `DocumentStoreManager` остаётся значение по умолчанию `false`. Это один внутренний режим ресурсного учёта для последующей интеграции R03–R09; пользовательского переключателя нет.

Публичные форматы документа v2 и сессии v3 не изменены. Старый writer и обычный `EventsStore.prepareToSave()` не публикуют новые поля. Мапперы модели в DTO передают метаданные только при явном `includeMetadata = true`. Проверенный здесь JSON round-trip — это `prepareToSave → JSON → init` внутреннего стора; загрузка новых файлов через публичный codec, IndexedDB и Drive появится на следующих этапах. Включать новый режим в приложении до этой интеграции нельзя.

## Изменения

`EventIdentity.ts` задаёт общие метаданные для DTO, одиночных и повторяемых моделей:

- `eventUid` идентифицирует сохранённое событие или сегмент расписания;
- `seriesUid` связывает сегменты одной исходной серии;
- `occurrence = { seriesUid, occurrenceDate }` хранит исходное вхождение выделенного события независимо от последующего переноса;
- `originalPlan` сохраняет независимый снимок плана до выполнения или выделения;
- `plannedOperation` и `actualOperation` передают контракты R01 вместе с ID движений, ценовыми ссылками и контекстом кэшбэка.

UID создаются командами создания, копирования и разбиения. Для вхождения используется детерминированный ключ `occurrence:<экранированный seriesUid>:<исходная дата>`. Временные числовые `id` остаются для существующих UI-потребителей и могут меняться при правке/загрузке. Мапперы, сохранение, чтение и подготовка строк календаря новые UID не генерируют. Новый режим требует передать ID при `init`; мигратор R03 будет назначать их старым данным до загрузки в стор.

Редактирование сохраняет UID и происхождение события, даже если форма передала другие значения. Изменение даты выделенного события не меняет ключ исходного вхождения. Копирование создаёт самостоятельный одиночный план с новым UID, без происхождения, фактических движений, прежнего снимка и подтверждения выплаты. Если копируется ресурсный факт, его реальные количества и счета становятся плановыми движениями. ID всех движений копии и ссылки `pricing`/`cashback` перенумеровываются согласованно.

При разбиении расписания сегменты получают разные `eventUid`, сохраняя один `seriesUid`. Новая копия движений фрагмента не использует ID движений другого сегмента. До выполнения, удаления или выделения проверяются границы расписания и принадлежность даты шаблону. Повторный запрос к уже исключённой дате ничего не меняет и не публикует повторное изменение. Для одиночного плана повторное выполнение прежнего числового ID также не добавляет факт.

Отмена выполнения восстанавливает сохранённый одиночный план с тем же UID и исходным ключом. Она не возвращает старую серию целиком. Правка или сдвиг оставшейся серии исключает уже выделенные/выполненные вхождения до публикации; отмена одного из них не возвращает выполненных соседей. Этот механизм работает и после внутреннего JSON round-trip, и когда последний сегмент серии уже исчез. Если факт создан напрямую без исходного плана, отмена преобразует его ресурсные стороны в план.

Метаданные и снимки копируются при переходах DTO ↔ модель. Правка входного DTO, полученного снимка или копии не меняет сохранённый исходный план. В новом режиме до загрузки и создания проверяются уникальные UID, ключи вхождений, ID текущих движений и внутренние ссылки на движения; редактирование/выполнение также проверяет конфликт ID движений до изменения стора. Полная проверка типов, категорий, счетов, ресурсов и совместимости плана/факта относится к codec R03 и командам R05.

`EventCacheStructure` передаёт `eventUid`, `seriesUid`, исходное вхождение и его `occurrenceKey`. Рендер получает устойчивую ссылку без генерации ID; завершённая строка и прежняя плановая строка вхождения имеют одинаковый ключ.
