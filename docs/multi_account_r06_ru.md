# R06: количества, прогноз и текущая оценка

Дата: 1 ноября 2026 года. Этап [плана реализации](multi_account_implementation_plan_ru.md).

## Индексы и граница прогноза

`HoldingsIndex` строит накопленные десятичные количества по `(accountId, resourceId)` и `actualOperation.effectiveDate`. Дата и длительность карточки не добавляют повторных финансовых движений. Входные события не сортируются и не изменяются; после построения чтение позиции использует бинарный поиск по датам.

`ForecastIndex` хранит непересекающиеся корзины назначения: счёт, категория счетов без счёта и полное отсутствие назначения. Одиночный план учитывается один раз на своей дате начала, даже если карточка многодневная. Расписания не разворачиваются в историю: используется `OccurrenceCounter.countDates`, одинаковые шаблоны с одинаковыми границами объединяются для расчёта, а индивидуальные записи остаются доступными в детализации просроченного.

Для даты `d` и точки `T` расчёт использует факты строго до начала `d` и оставшиеся планы в `[T, d)`. Это эквивалентно остатку на начало `T` плюс факты и планы интервала. Для `d <= T` остаются только факты. Последний факт документа больше не определяет границу ресурсного прогноза. Сегодняшний факт входит в завтрашний остаток, будущий — только после своей даты; выполненный план исключён командами R05 и второй раз не считается.

Просроченное рассчитывается отдельно до `T`: записи содержат название, стабильный UID/серию, число вхождений и количества. Оно не переносится автоматически на сегодня. В количествах отдельно сохраняются приход и расход, включая случай нулевого сальдо.

Даты индексов — календарные даты документа. Счётчик получает их через UTC-представление календарного дня с явным нулевым смещением; это не изменение глобального `DateTime.timezone`. Прежний числовой счётчик сохраняет свой режим по умолчанию. Точка `T` по умолчанию определяется в IANA-поясе документа, её также можно передать явно.

## Снимок цен и полнота оценки

`createPriceSnapshot` создаёт независимый замороженный набор текущих цен с версией и временем пересчёта. `ValuationService` использует только этот набор: прямую цену в основной валюте либо один дополнительный валютный шаг. События, цены плановых/будущих сделок и журнал отмен не являются источником оценки при чтении.

Учитываются знак количества и явный ноль цены. Отсутствующая цена, отсутствие цены валюты котировки и неподдерживаемая цепочка возвращаются как причины неполной оценки. Результат содержит известную сумму и все неоценённые ненулевые позиции с их местами назначения. Нулевая позиция не требует цены. Переполнение числовой политики R01 остаётся явной ошибкой.

Промежуточные произведения и сумма сохраняют десятичную точность. Денежный итог округляется один раз в масштабе основной валюты; округление каждой позиции отдельно не применяется. Количества остаются прежними. Прошлые даты получают текущую фиксированную оценку с явным `valuationBasis: 'current-prices'`.

## Проекции категорий

Исходный набор позиций содержит каждое движение ровно в одной корзине. Из него строятся два представления:

- счета и категории счетов: собственные позиции счетов плюс отдельные планы категории;
- категории ресурсов: те же позиции, сгруппированные по ресурсу, включая нераспределённые планы.

Группировки не складываются между собой. Общий итог оценивает исходные позиции через пересечение `includeInGrandTotal` категории счёта и категории ресурса. Для полностью нераспределённого плана применяется только категория ресурса. `showInSummary` управляет строками сводки, а не денежным итогом. Подробные позиции сохраняются и при скрытой строке. Архивирование счёта/ресурса само по себе не исключает его количества.

Назначение плана категории конкретному счёту этой же категории сохраняет итог группы и общий итог. Перегруппировка между включённой и исключённой категорией корректно меняет общий итог без перестроения финансовой истории.

## Кэш и потребители

`EventsCache.resourceBalances` предоставляет:

```ts
const day = eventsCache.resourceBalances.get(documentId, '2026.11.04', {
  forecastFrom: '2026.11.03',
  mode: 'forecast' // либо actual: только факты
})
const week = eventsCache.resourceBalances.range(documentId, '2026.11.01', '2026.11.08')
```

`ResourceBalanceReport` содержит ID документа, дату, точку прогноза, часовой пояс, исходные позиции с фактом/планом и приходом/расходом, обе проекции категорий, нераспределённое, просроченное, снимок цен и результат оценки. Это данные для календаря, списка дня и справочников R07–R08. Все дни одного вызова `range` используют один экземпляр снимка цен. Возвращаемые отчёты и вложенные структуры заморожены.

Расчёт читает опубликованный DTO через `DocumentTabsStore.getDocumentData`, поэтому запрос не пересериализует даты моделей и не создаёт локальную правку. Данные адресуются исходному `documentId`, включая неактивные вкладки. Закрытый документ не возвращает старый результат.

Кэши разделены на количества, группировки и оценённые отчёты. Изменение цены обновляет снимок и оценку готовых позиций, сохраняя количества и группировки. Изменение категории пересобирает группировки, сохраняя количества. Правка движений перестраивает индексы. Версии справочников и событий читаются и при попадании в кэш для корректной подписки MobX.

Число контекстов документов ограничено 16, каждый кэш дат — 512 записями, скомпилированных расписаний — 128. `range` ограничен 512 днями; одиночный запрос может считать произвольный поддержанный день без обхода всех промежуточных дней. `diagnostics` показывает размеры и число построений/чтений для проверки поведения.

`ResourceBalanceClock` публикует время и обновляет день с шагом 30 секунд; предусмотрен явный `refresh`. Таймер запускается жизненным циклом только внутреннего ресурсного режима и освобождается вместе с приложением. Прежний запуск приложения не получает дополнительный таймер.

Календарные `EventCacheStructure` сохраняют независимый замороженный `financial` с ресурсными операциями и документ-источник. Прежние скалярные методы `credit`/`debit` не сворачивают ресурсный граф в число: они сообщают о необходимости `resourceBalances`. `getAggregatedBalanceResult` возвращает явную недоступность междокументного денежного итога с объяснением; прежний числовой метод также не возвращает ложный ноль или сумму несопоставимых валют. Публичный режим по умолчанию остаётся прежним до R09.

## Воспроизводимый замер

Скрипт [benchmark-resource-balances.cjs](../scripts/benchmark-resource-balances.cjs) использует [общий генератор](../src/test-utils/resourceBalanceBenchmarkData.ts): 10 000 фактов, 2 000 одиночных планов, 100 расписаний с 2010 года, 20 счетов, RUB/USD, диапазон 147 дней. Запуск:

```text
node scripts/benchmark-resource-balances.cjs legacy
node scripts/benchmark-resource-balances.cjs resource
```

Пять прогонов, медиана в миллисекундах; Node v24.12.0, Windows, Intel Core i5-10400F 2.90 GHz. Исходные выборки сохраняются в `artifacts/r06/legacy.json` и `artifacts/r06/resource.json`. Загрузка/codec и изменение документа до запроса переоценки исключены из времени чтения.

| Измерение | Прежний скалярный путь | Ресурсный путь |
| --- | ---: | ---: |
| Построение индекса | 1.787 | 239.469 |
| Первое чтение диапазона 147 дней | 7.899 | 468.961 |
| Повторное чтение диапазона | 0.102 | 0.369 |
| Переоценка диапазона после USD 90 → 95 | Не поддерживается | 25.126 |

Это сравнение стоимости разных результатов: прежний путь получает заранее сведённые к RUB числа и возвращает скаляр, новый — десятичные позиции, группировки, просроченное и полноту оценки; правила границы прогноза также различаются. Холодный ресурсный расчёт на этом наборе занимает около 0.7 секунды вместе с построением, что нужно учитывать при подключении больших документов в R07–R08. Прогретое чтение и смена цены используют готовые данные. Скрипт проверяет, что цена не увеличивает `indexBuilds` и `quantityReads`; для этого не требуется обход финансовой истории при чтении.

Во время R06 устранён повторный расчёт группировок при смене цены: на том же наборе эта операция сократилась примерно с 266 до 25 мс. Абсолютные времена не используются как нестабильные пороги тестов; проверяются корректность, повторное использование индексов и ограничения кэшей.
