# R04: документные справочники и единая публикация

Дата: 1 ноября 2026 года. Этап [плана реализации](multi_account_implementation_plan_ru.md).

## Сторы документа

`DocumentStoreManager` в ресурсном режиме создаёт `ProjectsStore`, `EventsStore` с поддержкой движений и `ResourceCatalogStores`. Последний объединяет документные сторы счетов, ресурсов, единиц, категорий баланса, журнала цен, категорий и месячных условий кэшбэка. Общая реализация коллекции — `DocumentCatalogStore`; отдельного глобального изменяемого списка счетов нет.

Каждый справочник предоставляет неизменяемые `list`/`getById`, команды `upsert`/`replace`/`remove`, независимый `snapshot()` и наблюдаемую `version`. Вложенные объекты и массивы также заморожены. Месячные условия идентифицируются парой `[accountId, month]`, поэтому правка условий обновляет запись, а следующий месяц добавляет новую.

Версия справочника меняется только при изменении его содержимого и не является sync-версией документа. Переименование счёта, смена категории, цены или условий не пересоздают события и не меняют `EventsStore.version`. Неизменённые справочники сохраняют свои версии. Отсутствующие необязательные блоки не превращаются в пустые массивы при чтении.

`DocumentStores.resourceStores` доступен через существующие методы провайдера вкладок и новый `useDocumentStores(documentId?)`. Форма может удерживать исходный ID при переключении активной вкладки. Закрытие/очистка/освобождение документа отключают callbacks старых сторов; оставшаяся ссылка на справочник не позволяет записать правку в закрытый или пересозданный документ.

## Одна публикация

Добавлен callback `onDocumentChanged`: он отвечает за сохранение полного документа независимо от того, какой стор изменился. Прежние `onEventsChanged`/`onProjectsChanged` остаются уведомлениями для потребителей. `DocumentTabsStore` фиксирует данные и увеличивает `localVersion` через общий callback, а не отдельно для каждого изменённого стора.

Составные правки выполняются через `DocumentTabsStore.editDocument(documentId, edit)`:

1. Менеджер собирает независимый полный черновик из текущих сторов.
2. Синхронный callback изменяет только черновик.
3. Новый codec проверяет весь ресурсный граф, включая ссылки и точность количеств.
4. Проверенные данные применяются к существующим экземплярам сторов внутри одной MobX action; промежуточные callbacks подавлены.
5. Публикуется один итоговый снимок, один прирост `localVersion` и одна запись сессии.

Ошибка callback или проверки не меняет живые сторы, их версии и сохранённую сессию. Возврат Promise отклоняется: внутри подготовки нельзя ожидать сеть или выполнять асинхронную часть команды. Пустая правка не публикуется. Валидация отдельного `upsert`/`remove` также проходит через полный черновик, поэтому удаление используемого справочника отклоняется до изменения данных.

Это инфраструктура для R05; правила выполнения покупок, отмены и обновления цены сделки остаются задачей команд операций. Составная команда изменяет черновик, а не вызывает отдельные записи живых сторов.

## Внутренний маршрут

`DocumentRuntime` выбирает согласованный набор: создание пустого документа, чтение/запись файла, чтение сессии, версию сессии, режим сторов и персистентность. `legacyDocumentRuntime` остаётся значением по умолчанию. `createResourceDocumentRuntime(context)` включается явно через `createApplication({ documentRuntime })` либо конструктор `DocumentTabsStore`; контекст задаёт подтверждённую валюту и часовой пояс. По умолчанию такой режим использует `ResourceDocumentPersistence`, документ v3 и сессию v4.

Выбранный codec используется также для согласованного чтения Drive, сохранения, pull, экспорта/импорта и восстановления вкладок. Миграция старых документов остаётся отдельным действием R03 на копии; внутренний runtime не назначает валюту старым суммам автоматически. Прежний маршрут продолжает отклонять ресурсный граф и сессии v4. Публичный интерфейс переключается в R09 после готовности расчётов и форм.

При инициализации и применении удалённого снимка пользовательская публикация не вызывается. Восстанавливаются все справочники и события, сохраняются экземпляры сторов и корректные отпечатки. Новый ресурсный документ получает известную базу пустого содержимого, чтобы Reload не превращал пустую вкладку в локальную правку. Отправленный снимок остаётся независимым от последующих изменений справочников; более поздняя правка остаётся несохранённой после ответа Drive на прежний снимок.

Локальная ошибка записи оставляет видимую правку и сообщение об ошибке. Повтор сохраняет весь граф через прежний механизм очереди/архивирования; данные не объявляются записанными до успешного завершения.
