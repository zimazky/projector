# Этап 0 — воспроизводимые проверки

Исходная ветка: `per_document_stores_glm5_v1`. Коммит: `d0dbc12b8981e9f71ea687db9b9cd53b006b088d`. Перед началом рабочее дерево было чистым. Окружение: Windows, Node.js 24.12.0, npm 11.12.1. Зависимости и lockfile на этом этапе не обновляются.

## Запуск

Для проверки текущего checkout после установки зависимостей:

```powershell
npm ci --no-audit --no-fund
npm run verify:baseline
```

Чтобы сохранить существующий `node_modules`, установку следует выполнять в отдельном checkout. Именно этот вариант использован при реализации этапа:

```powershell
git worktree add --detach .remediation-tmp/clean d0dbc12b8981e9f71ea687db9b9cd53b006b088d
Push-Location .remediation-tmp/clean
npm ci --no-audit --no-fund
Pop-Location
npm run verify:baseline -- --root .remediation-tmp/clean --out artifacts/remediation-2026-10-31/before
```

Для проверки незакоммиченных исправлений в том же checkout после исходного прогона копируются только изменённые исходники, `package.json`, тесты и скрипт проверки. `.env`, существующий `node_modules`, пользовательские данные и результаты сборки не копируются. После коммита достаточно создать отдельный checkout нового коммита и повторить `npm ci`.

Скрипт выполняет typecheck, lint без исправлений, два полных запуска Jest, production-сборку и два режима npm audit. Для каждого шага сохраняются exit code, длительность и лог; ESLint, Jest, webpack и аудит также сохраняют JSON. В `summary.json` есть коммит, состояние рабочего дерева, версии Node/npm и SHA-256 lockfile. Повторный запуск требует нового каталога отчёта. Каталоги `artifacts` и `.remediation-tmp` исключены из Git; они не предназначены для публикации на Pages.

Код выхода скрипта ненулевой при нарушении проверки, обнаружении advisory или ошибке аудита. Для аудита `advisories` отличается от `error`: сетевой сбой или некорректный ответ не считается успешным аудитом.

Проверки запускаются с `TZ=UTC`. Случайные входные данные DateTime воспроизводимы: seed по умолчанию `20261031`, seed и аргументы входят в имя теста. Для другого набора:

```powershell
$env:DATETIME_TEST_SEED = '42'
npm test -- --runInBand src/7-shared/libs/DateTime/DateTime.spec.ts
Remove-Item Env:DATETIME_TEST_SEED
```

Генератор локален для тестов дат и не подменяет `Math.random` приложения. Асинхронные регрессии используют `src/test-utils/deferred.ts`: тест явно завершает или отклоняет Promise API без таймеров.

## Фикстуры и резервные данные

Все файлы в `src/test-utils/fixtures` синтетические, без пользовательских данных и действительных Drive ID:

- `legacy-document.json`: исходный формат без schemaVersion, проект, выполненные операции и запланированное событие. Остаток выполненных операций — 875.
- `repeating-document.json`: ежедневное повторение с конечной датой, отдельное планируемое событие и история поступлений/списаний. Остаток выполненных операций — 1600.
- `legacy-tabs.json`: две вкладки, одна связана с фиктивным Drive ID; старая структура без `sync`, с предупреждениями о локальных изменениях. Содержимое вкладок задаётся первыми двумя файлами.

Тесты проверяют round-trip событий через доменные сторы, восстановление двух документов без API и сохранность вкладки/локального снимка после отказа отложенной записи. Они не утверждают корректность старого dirty-tracking: его миграция остаётся задачей следующих этапов.

Перед будущим изменением формата хранения нужно выгрузить исходный localStorage из браузера приложения. Следующий код для консоли разработчика только читает ключи документов и скачивает отдельный файл; данные в браузере не изменяются:

```javascript
const backup = {
  capturedAt: new Date().toISOString(),
  origin: location.origin,
  entries: Object.fromEntries(
    Object.keys(localStorage)
      .filter(key => key === 'documentTabs' || key.startsWith('document_'))
      .map(key => [key, localStorage.getItem(key)])
  )
}
const backupUrl = URL.createObjectURL(new Blob([JSON.stringify(backup, null, 2)], { type: 'application/json' }))
const backupLink = document.createElement('a')
backupLink.href = backupUrl
backupLink.download = `projector-backup-${Date.now()}.json`
backupLink.click()
setTimeout(() => URL.revokeObjectURL(backupUrl), 1000)
```

Проверить, что скачанный JSON содержит `documentTabs` и нужные `document_*`. Хранить вне репозитория. При миграции работать на копии и оставлять этот исходный файл. Реальные данные на этапе 0 не читались и не мигрировались.
