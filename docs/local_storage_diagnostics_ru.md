# Как выяснить причину ошибки локального сохранения

В локальную версию добавлены конкретная причина и раскрывающийся блок «Подробности ошибки». Публикация этой доработки не выполнялась. Сам по себе экспорт сессии не освобождает localStorage.

1. Нажмите «Повторить локальное сохранение» для получения свежей ошибки.
2. Откройте «Подробности ошибки».
3. Посмотрите «Хранилище», «Ошибка браузера», «Операция», размер неудавшейся записи и уже сохранённых категорий.

| Результат | Значение |
| --- | --- |
| QuotaExceededError / NS_ERROR_DOM_QUOTA_REACHED | Браузер отклонил запись из-за квоты указанного хранилища (localStorage или IndexedDB) |
| SecurityError / NotAllowedError | Запрещён доступ к хранилищу |
| Подготовка JSON сессии | Ошибка сериализации произошла до обращения к Storage |
| Запись резервной копии перед миграцией | Не удалось сохранить исходник старого формата; текущая сессия ещё не заменялась |
| Запись текущей сессии | Не удалось заменить documentTabs новым полным снимком |

Объём показан как оценка размера строк UTF-16, не как точная занятость диска. Сумма включает ключи и значения; размер неудавшейся записи показывает её значение. Это не измерение лимита или свободного места. Замена текущей сессии не означает добавление к объёму всей новой строки сверх старой. Категории разделяют текущую сессию, прежние document_*, резервные documentTabs.backup.* и другие записи того же сайта.

Диагностика не содержит содержимого документов, имён файлов и произвольных ключей. Ошибка чтения размеров не скрывает первоначальный сбой. Старые записи и резервные копии автоматически не удаляются. Если причина остаётся неясной, достаточно передать название ошибки, операцию и показанные размеры; сам экспорт документов для диагностики не требуется.

Доработка проверена TypeScript приложения и E2E, ESLint, полным Jest, production-сборкой и сценарием Chromium с контролируемым превышением квоты. Результаты и логи — в `artifacts/storage-diagnostics`. Это проверка диагностики, а не установление причины в пользовательской вкладке: её состояние в этой работе не читалось.

После диагностики переполнения при создании архива на 5,33 МиБ поверх примерно 6,40 МиБ localStorage включена [миграция в IndexedDB](indexed_storage_migration_2026-11-01_ru.md). Операция «Транзакция сессии и резервной копии IndexedDB» подтверждается только после complete; архив и сессия применяются вместе. Размеры категорий относятся к localStorage и не измеряют занятую ёмкость IndexedDB. Если при сбое IndexedDB размеры localStorage недоступны, это не доказывает, что оно пустое.
