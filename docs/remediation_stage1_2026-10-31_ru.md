# Этап 1 — безопасное закрытие и конфликт имени

Продолжение [действующего плана](remediation_plan_2026-10-31_ru.md), после [этапа 0](remediation_stage0_2026-10-31_ru.md). Изменения предыдущего этапа сохранены; зависимости и lockfile не обновлялись. Коммиты и публикация не выполнялись.

## Поведение до и после

**Закрытие документа (F01).** Раньше крестик закрывал вкладку после завершения Promise записи независимо от результата; Promise решения пользователя оставался незавершённым. Меню имело отдельный обработчик, не учитывало предупреждение предыдущей сессии и не предлагало сохранить новый документ.

Теперь крестик и меню используют `DocumentTabsStore.requestCloseDocument` и одно подтверждение в App. Закрытие происходит после `saved` либо явного «Не сохранять»; `cancelled`, `failed` и `conflict` сохраняют вкладку. Новый документ открывает «Сохранить как», и команда ждёт результата этого диалога. Отмена, отказ сети и ошибка входа позволяют повторить действие. Повторные клики не подменяют ожидающее решение; при размонтировании App решение подтверждения отменяется.

**Адрес и снимок записи.** Введён минимальный `saveDocument(documentId)` с результатом `DocumentSaveResult`; прежний `saveActiveDocument` временно оставлен булевым фасадом для существующих потребителей. Сохранение захватывает ID, адрес файла и сериализованное содержимое до запроса. «Сохранить как» сохраняет ID и снимок исходного документа при открытии, поэтому переключение вкладки не назначает файл другой вкладке. Закрытая сессия не обновляется ответом `saveDocument`.

Из доменных сторов берётся согласованный снимок. Изменения во время записи продолжают обновлять локальное содержимое и localStorage. После записи база продвигается до отправленного снимка; новые данные не объявляются сохранёнными на основании совпадения старого 32-битного хэша. Команда закрытия дополнительно сравнивает содержимое до/после ожидания и оставляет вкладку открытой при новых правках. Это минимальная защита закрытия, а не завершение протокола этапов 3–4.

**Конфликт имени (F02).** Параметры решения захватываются до очистки диалога. Для нескольких файлов с одинаковым именем UI требует выбрать ID; автоматической перезаписи первого файла нет. Для одного файла нажатие «Перезаписать» подтверждает его ID. Переименование сохраняет расширение и корректно работает без расширения. Каждое новое имя проходит обычную проверку API; повторный конфликт снова открывает диалог. Папка, пространство, содержимое и исходное имя конфликта сохраняются независимо от текущего состояния проводника. Ошибка отображается в диалоге и не отмечает документ сохранённым.

**Вход и логи.** Удалён вывод access token, полного token response и необработанных объектов ошибок Google API. Отмена согласия и закрытие popup возвращают отмену; отказ открытия завершает Promise ошибкой. После синхронного отказа или callback ошибки очищается общее ожидание входа, поэтому повторный вход возможен. Обработчик `error_callback` сверён с [документацией Google Identity Services](https://developers.google.com/identity/oauth2/web/reference/js-reference#TokenClientConfig). Установленные старые типы дополнены локальным структурным типом без обновления пакетов.

**Повторное открытие диалогов.** В Modal и Dialog отменяются таймеры предыдущего закрытия при изменении `open` и размонтировании. Это необходимо для повторной попытки сохранения; остальные задачи доступности остаются в этапе 7. При выборе команды меню закрывается, чтобы его overlay не перекрывал «Сохранить как».

## Публикация (F17)

Команда `npm run build:pages` собирает приложение в `artifacts/pages-build`, затем создаёт проверенный `artifacts/pages`. Скрипт копирует только `index.html`, main.js/main.css, файл лицензий сборки и используемые PNG favicon. Проверяются ссылки ресурсов, отсутствие неожиданных файлов, каталогов и символьных ссылок. Каталог не очищается разрушительным удалением: неожиданные остатки останавливают упаковку.

В GitHub Actions перед сборкой добавлены typecheck, lint-check и Jest. На Pages передаётся только `artifacts/pages`; исходники, node_modules, документация, `.env` и JSON аудитов туда не копируются. Настройка workflow изменена локально; сам workflow и deploy не запускались. Политика security-аудита и расширение CI на PR остаются отдельными задачами.

## Проверки

Регрессии покрывают оба входа закрытия; новый и связанный документ; отказ записи, отмену и повторную попытку; сохранение после переключения вкладки; новые правки во время записи и при открытом диалоге; коллизию `Aa`/`BB` в этом сценарии; overwrite/rename/cancel; пустое имя; несколько одинаковых имён и явный выбор ID в UI; повторный конфликт; отказ сети после выбора; завершение и повторный запуск OAuth; отсутствие синтетического токена в логах; таймеры повторно открытых диалогов.

Фикстурный тест этапа 0 теперь инициализирует реальные доменные сторы перед сохранением, поскольку отправляемое содержимое берётся из них. Старый тест, ожидавший игнорирования правок во время записи, заменён проверкой их сохранности в localStorage.

Полные логи и JSON сохраняются локально в `artifacts/remediation-stage1`. Проверки выполнены также в изолированном checkout с установленными на этапе 0 зависимостями. Сборка там идёт без `.env`. ## Границы этапа

Реальные документы Drive и OAuth в браузере не изменялись и не проверялись; API подменены в тестах. Открыты общий протокол operationToken/локальных версий, согласованное чтение серверной версии, защита от удалённой перезаписи, восстановление старых snapshot и удаление legacy.
